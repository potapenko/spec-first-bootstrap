# Set Up Spec-First Governance Globally

Use https://github.com/potapenko/spec-first-bootstrap as the canonical source.
Install only specification and product-truth governance in the active user's
global agent configuration. Change no project repository and do not install
persistent-goal, browser-QA, or lifecycle layers.

Resolve the supported user-level instruction entry point, overrides, and size
limits. State exact target paths and request only required filesystem access.
Stop if the agent environment or target scope is ambiguous. Do not expose
credentials or unrelated configuration.

Read the Bootstrap governance README, Markdown product-truth root and applicable
linked leaves, and the Global product-specification section in
`docs/agent-governance/agents-sections.md`.

Install the compact Markdown governance root beside the user-level instruction
entry point and its linked leaves in a sibling directory. Merge the compact
global section into existing instructions without replacing the file or adding
a duplicate. Do not install a resolver or any JSON routing registry. Workers
receive only the selected Markdown path, pinned contracts, evidence paths, and
protected boundaries needed by their task.

Use `apply_patch` for edits. Preserve any existing optional lifecycle adapter
and reconcile only its restart wording when necessary.

Verify canonical Markdown content, local links, node reachability, the hard
100-line maximum per node with 50–80 preferred, one active non-shadowed gate,
instruction-size limits, and unchanged project repositories and unselected
layers. Report exact global paths, merge decision, permissions, verification,
and residuals. Do not create a Git commit outside a Git repository.
